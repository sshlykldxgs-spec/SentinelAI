# SentinelAI 黑盒评委模拟测试

日期：2026-10-12（Asia/Shanghai）。目标是首次用户通过准备合理资料，经UI完成完整分析。本轮不是开发或比赛材料制作；没有修改核心代码、凭据、真实配置、数据口径或历史记录，没有Git操作。资料固定后只尝试一次Live，不因失败调整输入重跑。

## 结论

**本案例未完成完整分析：Planner成功，Research在45秒请求超时处失败，后三个Agent未执行，没有最终报告。** 上传和任务创建可通过UI完成，但当前默认超时及失败体验阻止了这位模拟评委到达最终决策。不是因为“业务发现风险”而失败，而是程序执行路径的请求超时。

这个结果不能推翻此前固定Demo数据上五阶段Live成功，也不能用此前成功替代本案例验收。本轮只有一次案例尝试，不作为成功率统计。

## 测试案例与公开来源

案例：红海航运扰动背景下，一家**虚构欧洲工业设备企业**制定2024年2月底之后30天的关键部件采购决策。需要区分交付与质量，核查低库存和备用来源，评估维持订单、库存缓冲、空运或第二来源；合同/预算变更需人工批准。

公开背景：IMF，2024-03-07，*Red Sea Attacks Disrupt Global Trade*：

<https://www.imf.org/en/blogs/articles/2024/03/07/red-sea-attacks-disrupt-global-trade>

本轮在2026-10-12取得并检查公开页面。文章描述2024年最初两个月苏伊士贸易量同比下降约50%、巴拿马约32%，并讨论绕行造成统计时点变化。这是历史宏观背景，不是当前航运状态、供应商实测延误或未来概率；Agent没有网络检索工具。公开材料只作为用户上传的来源摘要。

所有企业、供应商和数值**明确标注SIMULATED**，没有内部机密。不是完美输入：

- 正常：Aster Controls准时率97%、缺陷0.7%；区域来源Fjord Bearings 98%/0.5%。
- 异常：Beacon Drives准时率76%、缺陷4.1%、9日库存、无已认证备用；Elm Power准时率96%但缺陷3.8%，不能合并质量和交付结论。
- 信息不完整：Dune Sensors库存天数为空、Elm Power备用数量为空。缺少订单数、质量样本数、未交订单、承诺日期、消耗速度、替代认证、加急报价和违约条款。
- 所有记录是单期快照，不能造趋势、订单加权平均或确定停产日期。未来30天是问题范围，不是原始数据时间窗口。

## 输入资料与用户路径

输入文件保存于 `blackbox_case_2026-10-12/`：

1. `suppliers_simulated.csv`：6家模拟供应商，交付、质量、交期、USD月支出、组件、路线、库存与备用数量、2024-02快照标记。
2. `business_brief.txt`：业务问题、单位、口径与未知项约束。
3. `public_source_note.txt`：公开URL、发表日期、核实背景及应用边界。

使用的是当前UI支持的CSV/TXT，没有使用不支持的Markdown格式。CSV沿用当前示例基本列名，另外添加普通业务列；这是用户整理资料，不是修改应用。测试者参考了可见的文件格式/示例，不能把它当作零资料指导的随机用户研究。

原共享页面第一次打开时Live禁用、显示模型未配置；已有CC Switch凭据不会自动进入这个后端。为了保留用户历史，使用已有只读桥接在独立本地测试实例加载同一DeepSeek配置。测试实例后端18001/前端15174，不是公开部署；普通评委需提前完成模型环境配置，准备资料本身并不足以让无凭据环境运行Live。

全部任务操作通过浏览器：打开总览 → 取消预选suppliers.csv/brief.txt → 上传上述3文件 → 填写问题 → 选Live → 点击启动 → 查看五阶段 → 逐个打开Agent输出 → 查看证据中心与报告页。

没有直接调用项目内部API或修改数据库。浏览器正常产生UI请求与SSE；测试层被动观察UI收到的数据和模型响应元数据以计时计数，未替换响应或伪造输出。用户另行授权了API调用，但本轮仍用UI主流程。核心代码保持不变；仅独立进程加载现有配置、关闭重试并附加只输出非敏感元数据的观察器。

## 首次使用体验问题

| 观察 | 实测表现 | 影响 / 仅建议 |
| --- | --- | --- |
| 初始模型不可用 | 共享页面Live按钮禁用、模型未配置；已有CC Switch不自动生效 | 需开发者/文档解释服务端配置。建议提供明确可定位的配置状态入口，不宣称上传即可Live |
| 预选Demo资料 | 新任务开始默认选择suppliers.csv与brief.txt；用户须手动取消 | 可能无意混入旧示例，建议新资料上传时明确提示实际选择来源。此次确已取消，没有混用 |
| 启动前总览滞后 | 三份新资料上传并选中后，指标/矩阵仍显示旧suppliers.csv与Meridian等Demo供应商 | 选中资料与图表不一致，新用户可能误认为资料已被分析。建议显示指标针对的文件/运行状态，避免提前暗示新结果 |
| 上传入口 | 点击/文件选择操作清晰，支持类型与大小可见，3份文件均选中并生成来源记录 | 基本路径可用；长资料列表需要内部滚动，部分文件在当前视口看不到，已选择数有帮助 |
| CSV门槛 | 示例表头可用，额外业务列可作为证据，但没有上传时的字段映射/口径校验视图 | 普通用户需要知道基本列名与百分比定义；建议格式示例/映射反馈，不把任意CSV的可解析等同可量化 |
| Agent状态 | Research失败明显；后续仍显示“排队中”而非“未执行/因上游失败停止” | 新用户可能继续等待。应区分终态下游停止和可运行队列 |
| 耗时/错误 | 节点和时间线可看到Research 45.01秒、失败；提示“模型请求或任务预算超时” | 友好程度一般，无法分辨单请求/全任务，更无明确45秒限制说明。应提示具体范围和手动重跑后果；此次未点击重跑 |
| 失败详情footer | 失败Agent底部仍显示“完成于02:43” | 可能误读为成功；建议显示“结束/失败于” |

| 模式双标签 | 刷新后顶栏“新建Demo”与“当前Live”同时出现 | 虽然文字准确，新用户需理解两者不同。建议让当前任务模式更突出 |

## 程序失败与业务风险的区别

**程序结果失败**：Research在请求截止前没有完成，导致分析、审查、行动与报告无法交付。

**案例确有业务风险与信息缺口**：低交付、高缺陷、低库存和备用认证未知是固定模拟资料里的事实；不是系统完成风险分析后的审查结论。当前运行不能宣称自动识别并处理这些风险成功。Planner已规划核查，不等于最终建议得到业务证据支持。

## 建议与停止状态

最小建议仅记录：先将单请求/任务超时及下游停止状态对用户明确展示；对普通三文件任务评估Research响应耗时与负载，在获得授权后再讨论有限超时/输入精简。改进报告失败空态和新上传数据的来源显示。不要为成功删掉缺失信息、换成完美资料或自动循环重跑。

本轮没有重构/修复代码、修改密钥或真实配置、创建Git、提交推送或部署；没有审批或外部行动。只新增三份固定测试输入及本测试报告，临时测试配置与观察脚本不进入应用代码。结束后关闭独立测试服务，保持原服务和用户数据不变。测试实例关闭后内存运行记录不可恢复，但输入、截图与脱敏观察记录保留；没有最终报告可归档。

最终判定：**这位模拟评委能完成准备资料、上传和启动Live，但未能在本轮获得完整分析报告。**
